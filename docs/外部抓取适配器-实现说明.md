# 外部抓取适配器 · 实现说明（M4 独立部分）

**状态**：待实现　**配套**：《家庭信息助理系统-后端设计文档.md》§4.16 / §5.3 / §5.6 / §6
**本说明作用**：把"对着真实外部站点反复联调"的抓取部分从主开发会话独立出去。你（另一个会话的 AGENT）只需按本文档契约实现 3 个抓取适配器，之后主会话会自动接上注册表与调度。

---

## 1. 背景与分工边界

M4 里程碑包含"信息抓取"：机器人既能**定时抓**（订阅的 RSS / 预设信息源），也能**实时抓**（如"查一下三角洲密码门"）。抓取要对着真实站点联调，所以独立出去。

**你负责（本文档全部内容）**：
- 3 个抓取适配器（纯函数）：`rss` / `steam_news` / `delta_password_gate`

**主会话负责（你不用管，等你完成后会自动接上）**：
- 适配器注册表与 `/fetch` 路由、SSRF URL 校验（`validateFetchUrl`）
- 订阅/新闻/任务/记忆 模块（§5.2/§5.3/§5.6）
- 调度任务 `news_fetch`（每 6h 抓订阅）、`news_cleanup`（每小时清缓存）

> 一句话：**你只交付"能抓到正确数据的纯函数"**，写库、去重、推送、调度全由主会话做。

## 2. 接口契约（必须严格满足，否则注册表接不上）

```ts
// 抓取结果条目
export interface FetchedItem {
  title: string;                // 必填：标题
  url: string;                  // 必填：原文链接（去重键，主会话会 sha256(url)）
  summary?: string;             // 可选：摘要/简介（纯文本，别带 HTML 标签）
  published_at?: string | null; // 可选：发布时间 ISO8601 "YYYY-MM-DD HH:MM:SS"；未知传 null
}

// 适配器
export interface FetchAdapter {
  key: string;                  // 唯一键，订阅 preset_key 指向它
  label: string;                // 展示名，如 'Steam 新闻'
  fetch(params?: Record<string, unknown>): Promise<FetchedItem[]>;
  // params 约定：
  //   rss                  → { source_url }  (用户/订阅给的 RSS 地址)
  //   steam_news           → { appid? }       (Steam 应用 id，缺省用默认游戏)
  //   delta_password_gate  → {}               (内置目标，无需参数)
}
```

**三条硬约束**：
1. **纯函数，不碰数据库**。news_cache 的写入、去重、推送由调度器做，适配器只负责"抓到 → 返回条目"。
2. **不要自己实现 SSRF 校验**。URL 白名单/校验在注册表层（主会话），适配器只管按 params 抓。也不要绕过。
3. **失败就 throw**（中文可读 message，如 `"抓取超时: xxx"`）。上层会捕获记日志，不会崩服务。

## 4. 技术选型与运行环境

- **Node 22**（有全局 `fetch`）——**不要装 axios / request**，用内置 fetch。
- RSS/Atom 解析推荐 `fast-xml-parser`（`npm install fast-xml-parser`，轻量零传递依赖）；也可自选解析库，输出必须仍是 `FetchedItem[]`。
- **超时必须有**：fetch 带 `AbortSignal.timeout(10_000)` 之类，抓取失败 throw。
- **本机 WebFetch 工具不可用**（Claude 环境限制）——联调一律用 `curl` 先测目标站可达性，再写解析代码。
- 不用写密钥：本阶段三个 preset 都不需要 API Key；若某站点真需要，写 .env 由主会话统一管理，别硬编码进代码。

## 5. 三个适配器逐个说明

### 5.1 `rss`（通用 RSS/Atom）
- **输入**：`params.source_url`（RSS 地址）。
- **行为**：抓取并解析 RSS 2.0 / Atom / RSS 1.0 的条目。
- **输出**：每项 `{ title, url, summary, published_at }`。
- **注意点**：
  - `<description>` / `<content:encoded>` 常是 HTML，**清洗标签后截断**再做 summary，别把整段 HTML 塞进去。
  - 部分源没有发布时间 → `published_at: null`。
  - 编码坑：个别源是 GBK，注意 `response.arrayBuffer()` 后按 `charset` 解码。
  - 先用 curl 验证目标源可达（`curl -sS <url> | head -c 500`）。

### 5.2 `steam_news`（Steam 新闻）
- **输入**：`params.appid`（可选；缺省给一个常用游戏的 appid，如 DOTA2=570）。
- **行为**：抓取该 appid 的最新 Steam 新闻。
- **候选数据源（联调后二选一，以实测可用为准）**：
  - 官方 Web API：`https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid={appid}&count=10&maxlength=300`（GetNewsForApp 一般无需 key）
  - Steam 商店新闻 RSS：`https://store.steampowered.com/news/feed/app/{appid}`（确切格式需 curl 验证）
- **注意点**：
  - 国内访问 Steam 域名可能慢/偶尔不通，先 curl 测。
  - 返回的 `url` 形如 `https://store.steampowered.com/news/app/{appid}/view/{postid}`，稳定可用，直接拿来做去重键。
  - `published_at` 可能是秒级时间戳，转成 `"YYYY-MM-DD HH:MM:SS"`。

### 5.3 `delta_password_gate`（三角洲密码门爬虫）
- **输入**：无（内置目标）。
- **行为**：抓取"三角洲行动"游戏当前的密码门（门密码/通行码）信息，返回可读条目。
- **⚠️ 目标站点与页面结构待确认**：具体 URL、列表页/内容页结构，**以你在另一个对话里向用户确认到的为准**（可能涉及 UA、Cookie、防爬，都按用户给的来）。
- **输出建议**：每条密码门 = 一条 `FetchedItem`（`title`=门名称/编号，`summary`=密码/说明，`url`=来源页面）。

## 6. SSRF 与安全边界（重要）

- preset 适配器的目标 URL **尽量写死**，不接受任意 url 参数。
- `rss` 接受用户给的 `source_url`，但该 URL 会先过主会话注册表的 `validateFetchUrl()`：
  只允许 `http(s)`，拒绝私网/环回/链路本地/云元数据地址段（`127.*`、`10.*`、`192.168.*`、`169.254.*`、`172.16-31.*`、`169.254.169.254` 等）。
- **适配器内不要绕过上述校验**，不要拼出可变主机名，不要抓内网地址。
- 不抓需要凭据的页面；不硬编码任何密钥/API Key。

## 7. 上层怎么用（理解上下文用，不用实现）

- 订阅表 `subscriptions`：`source_type='rss'` 存 `source_url`；`source_type='preset'` 存 `preset_key`（= 适配器 key）。
- `news_fetch`（每 6 小时）：遍历 enabled 订阅 → 按类型调对应适配器的 `fetch(params)` → 按 `url_hash`（sha256(url)）去重写 `news_cache` → 记日志。**适配器只需返回条目，其余全自动**。
- `news_cleanup`（每小时）：删 `news_cache` 中超过 `settings.news_retention_days`（默认 4 天）的记录。
- 实时抓取：`POST /api/v1/fetch { source_type, preset_key? | source_url?, params? }` → 适配器结果返回给机器人。
