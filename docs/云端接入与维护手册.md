# 家庭信息助理 · 云端接入与维护手册

> **定位**：本地（M0-M5 应用代码）与云端（部署 + AstrBot 插件）之间的**权威接口文档**。
> **以本文档为准**：设计文档《家庭信息助理系统-后端设计文档.md》用于理解设计意图；**部署、接入、工具注册一律以本文档 + 实际代码为准**，两者冲突时以本文档为准。
> **配套**：《家庭信息助理系统-需求文档-v2.1.md》《家庭信息助理系统-后端设计文档.md》、云端 `homeassistant-tools-inventory.md`（插件已注册的 36 个工具，实测基准）。
> **更新协议**：本地每完成一次功能变更 → 更新本文档（新增端点/工具/调度）→ `npm run build` 验证 → 推 GitHub → 云端 `git pull` → 云端按需补注册工具。

## 1. 项目结构（实际实现）

**技术栈**：Node.js 22 + TypeScript + Fastify 5 + better-sqlite3（WAL）。ESM（`"type":"module"`），相对导入带 `.js` 后缀。

```
src/
├── index.ts             # 入口：config → db → 迁移 → 注册表 → Fastify → 调度器
├── app.ts               # 应用装配：日志(带 /w token 脱敏 serializer)、错误格式、路由注册、宽容 JSON body
├── config.ts            # 环境配置（见 §5）
├── lib/
│   ├── errors.ts        # AppError，统一 {code, message}
│   ├── auth.ts          # Bearer X-API-Key / ADMIN_KEY 鉴权钩子（timingSafeEqual）
│   └── identity.ts      # 身份注入中间件：x-platform/x-openid 头 → person 解析
├── db/
│   ├── index.ts         # 连接工厂（WAL/外键）
│   ├── migrations.ts    # 迁移 runner（schema_migrations 记录）
│   ├── migrate.ts       # npm run migrate
│   ├── backup.ts        # npm run backup（在线冷备，保留 7 份）
│   ├── registry.ts      # 表注册机制（描述符→建表+通用 CRUD，内部用）
│   ├── dao.ts           # now/today/parseJson/logOperation 辅助
│   └── migrations/      # 001_init.sql（16 表）+ 002_memory_fts_trigram.sql
├── modules/
│   ├── system/          # 身份/账户/画像/settings
│   ├── bills/           # 记账核心（CRUD/AA/统计/批量/变动查询）
│   ├── bills_web/       # 记账 Web（能力令牌 + /w/:token/* 页面 + CSV）
│   ├── tasks/           # 家庭共享任务
│   ├── news/            # 订阅/新闻//fetch + adapters/ 抓取适配器
│   ├── memory/          # 用户记忆（FTS5 trigram 中文检索）
│   ├── outbox/          # 待推送队列（生产/消费/回执）
│   └── internal/        # 表注册内部接口（ADMIN_KEY）
├── scheduler/           # node-cron 任务（见 §4）
scripts/
└── copy-assets.mjs      # 构建时把非 TS 资源（migrations/*.sql、templates/*.ejs）拷进 dist
```

**数据表**（001_init.sql，16 张 + 1 虚拟表）：`persons`、`person_identities`、`accounts`、`account_members`、`bills`、`tasks`、`subscriptions`、`news_cache`、`outbox`、`operation_logs`、`settings`、`user_memories`、`web_tokens`、`registered_tables`、`schema_migrations`、`user_memories_fts`(FTS5)。

**鉴权分层**：
| 面 | 凭据 | 说明 |
|----|------|------|
| API 面 `/api/v1/*` | `Authorization: Bearer <X_API_KEY>` | 插件/工具调用 |
| 身份 | 请求头 `x-platform` + `x-openid` | **插件注入**，后端解析 person，不是 LLM 参数 |
| 内部面 `/api/v1/_internal/*` | `Authorization: Bearer <ADMIN_KEY>` | 表注册，仅管理员 |
| 网页面 `/w/:token/*` | 能力令牌（URL 里的 token） | 只服务记账，见 §6 |

## 3. 工具注册（权威清单）

**与云端 `homeassistant-tools-inventory.md` 完全一致（36 个），本文档不再重复参数签名**，只强调注册时的硬约束与后端对应关系：

1. **工具名是既定契约**：已有 36 个名字（含语义）**不得改名/新建同义词**。新增工具前先对照 §2 端点表与 inventory：同作用必同名，新作用才新名字。
2. **身份不入参**：`x-platform`/`x-openid` 由插件从入站事件注入，LLM 猜不到也传不了。任何工具签名**不要**出现 platform/openid 参数。
3. **金额单位是「分」**：`amount` 工具层**直接收「分」整数**（`int(amount)`，1 元 = 100 分；插件**不做**元→分换算，需 LLM 自行换算，如 12.5 元 → 传 1250）。返回里的金额同样以「分」为单位。
4. **多账本歧义**：用户有多个账本时，记账/查账/待办需 `account_id`，否则后端 `ACCOUNT_AMBIGUOUS`，LLM 应反问指定。
5. **AA 规则**：`add_bill` 带 `participants`（名字数组）→ `status=pending`；`settle_bill` 结算。用户说「AA/平摊/垫付」先问清参与者。
6. **docstring 即工具描述**：AstrBot 用 docstring 生成 LLM 工具定义——参数名/类型/单位/枚举（如 type ∈ {income,expense}）都要写清。
7. **统一错误返回**：工具内 `self._api(...)` 失败返回失败字典（含 code/message），由 LLM 转述。

**已存在但未注册工具的端点**（云端可按需补，非必需）：`POST /news/:id/read`（标记已读，未读新闻在每日简报重复的关键）、`GET /profile` 与 `PATCH /persons/me/profile`（画像读写，当前无写入入口）、`POST /subscriptions/:id/refresh`（手动刷新订阅）。

### 3.1 方向 A 新增端点契约（2026-08-16，供云端注册强大查询/统计工具）

新增两个端点，**均不改旧接口**（`GET /bills`、`GET /bills/stats` 等保持原样，供旧工具继续使用）：

- **`GET /api/v1/bills/export`** —— 全量宽过滤查询/导出（无分页上限）：
  - 参数：`type / category / status / participant / month / year / from / to / amount_min / amount_max / account_id / format`（`format=json|csv`，默认 json）。
  - `amount_min/amount_max` 单位「分」（非负整数，非法返回 `INVALID_AMOUNT_MIN/MAX`）。
  - json 返回 `{ total, applied, items }`：`applied` 回显**实际生效的筛选**（含金额/日期区间），`items` 金额「分」。
  - csv 返回 `text/csv; charset=utf-8`（UTF-8 BOM + 防公式注入，金额「元」人可读，全量）。
  - 按身份头隔离：只导出当前 person 可见账户（多账本需 `account_id`，否则 `ACCOUNT_AMBIGUOUS`）。
- **`GET /api/v1/bills/stats/range`** —— 区间统计（合计尊重区间，修正旧 `billStats` 合计不带 year/month 的问题）：
  - 参数：`from / to / year / month / category / amount_min / amount_max / account_id`。
  - 区间推导：显式 from/to 优先；year+month→当月；year→全年；都不给→全量。
  - 返回 `{ income, expense, net, by_category, trend, applied }`：`net = income - expense`；`applied` 回显生效的日期区间/分类/金额区间；金额「分」。

> 设计原则：查询/统计工具返回 `applied`（回显实际生效的筛选 + total），让 LLM 能发现自己解释错了筛选（静默的查询误判靠回显兜底）。统计转图像由云端插件 matplotlib 渲染（后端只出结构化数据），云端可自行决定工作区按人子目录方案。

## 4. 调度任务（后端自动执行，插件无需实现）

| 任务 | 周期 | 行为 |
|------|------|------|
| `reminder_due` | 每分钟 | 到期任务 → outbox 提醒 |
| `bill_digest` | 每 5 分钟检查，到 `settings.bill_digest_time`（默认 21:00） | 当日账单变动日报 → outbox（家庭→成员/个人→本人） |
| `daily_brief` | 每 5 分钟检查，到 `settings.daily_brief_time`（默认 09:00） | 未读新闻 + 未完成待办 → outbox |
| `outbox_sweep` | 每 10 分钟 | 失败超限消息终态告警 |
| `news_fetch` | 每 6 小时 | 遍历启用订阅 → 适配器抓取 → 去重写 news_cache |
| `news_cleanup` | 每小时 | 清超期 news_cache（`news_retention_days` 默认 4） |

**插件职责**：只做 outbox 轮询消费（`GET /outbox/pending` → 投递 → `POST /outbox/:id/delivery` 回执）+ 用户主动查询时调 LLM 工具。**不参与**上述任何抓取/生成。

## 6. 记账 Web（能力令牌）

- 铸造 `create_ledger_link` → `POST /api/v1/web/tokens`，返回 `{url, token, expires_at}`；**token 明文仅回显一次**，库中只存 sha256。
- `url` = `PUBLIC_WEB_BASE` + `/w/` + token，浏览器经 ZeroTier 打开。
- mode=read 拒写；默认 30 分钟过期（`expires_in` 1-1440 分钟）；可 `revoke_ledger_link` 即时撤销。
- 安全：页面 EJS 全 `<%= %>` 转义 + CSP `script-src 'none'`；CSV 导出 `=+-@` 开头单元格加 `'` 前缀防公式注入；`/w` 访问日志 token 脱敏。

## 7. 功能变更 → 文档更新流程（维护约定）

本地每完成一次功能变更（新增端点/工具/适配器/调度/配置），必须同步：

1. **更新本文档**对应章节：新增端点进 §2 表、新工具名进 §3（先对照不重名）、新适配器进 §2.4、新调度进 §4、新配置进 §5。
2. **`npm run typecheck` + `npm run build`** 验证。
3. **推 GitHub**，云端 `git pull`。
4. **云端判断**是否需要补注册 LLM 工具（新端点若无对应工具，功能对用户不可达）——按 §3 硬约束补，补完更新云端 `homeassistant-tools-inventory.md`。

> 原则：**本地负责需求分析/设计/实现与文档；云端负责根据实际情况调整部署与工具注册。** 工具名以本手册 §3 + 云端 inventory 为唯一事实源，两端保持同步。
