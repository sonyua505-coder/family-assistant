## 1. 已定设计原则（BOT ↔ 后端对接）

1. **读工具 = 强大查询 + 自验证输出**：查询工具暴露宽过滤参数（类型/分类/金额区间/日期区间/参与人/关键词/分页），返回时回显"实际生效的筛选 + total 条数"，让 LLM 能发现自己的解释错误（静默的查询误判靠回显兜底，而不是靠报错）。
2. **写工具 = 窄动词 + 宽可选字段**：写操作保持按资源、按动词命名（`update_bill`/`delete_bill`/…），工具名是护栏；不做 `action` 枚举大工具。
3. **错误码结构化透传**：后端错误已是 `{code, message}`（`src/app.ts`），插件应提炼成"错误码 + 中文消息 + 合法值"给 LLM，支撑 LLM 自修正，而不是丢原始 body 文本。
4. **工作区 = 插件权威**：后端容器未挂载工作区目录，路径只有插件知道；文件操作一律由插件落地，后端只出数据。工具只收**相对路径**，插件 `resolve + is_relative_to` 校验，拒绝绝对路径/`../`/越界（安全红线见《BOT工作区机制.md》§6）。
5. **按人隔离**：工作区按 `normalize(umo)` 隔离，**群聊 = 全群共享一个工作区**；涉及个人数据（记账等）的导出/保存必须由插件按 `x-openid → person` 建子目录，避免群成员互相 grep 到财务数据。

### B. 文件导入记录数据

> **后端部分已完成（2026-08-16）**：新增 `POST /api/v1/bills/import` 宽容批量导入端点（逐行校验、跳过坏行、返回每行 `{index, code, message}` 明细，单次 ≤500）。**未改旧接口**（`/batch` 全有或全无语义保留给 `add_bills`）。详见《云端接入与维护手册.md》§3.2。插件侧（`save_uploaded_file` + LLM 解析）待云端适配。

- 用户发文件（如账单 CSV）→ 插件 `save_uploaded_file(relative_path)`（`await comp.get_file()` → 补全到工作区 → `shutil.copy` → 删 temp 副本）→ LLM 读取/解析 → 调 `POST /bills/import` 入库（**宽容导入**，坏行返回明细供 LLM 修复重试）。

- ⚠️ 必须 `await comp.get_file()`（用 `comp.file` 返回空串）；temp 副本不随事件清理，须手动删。

### G. 搜索/信息源工具增强（2026-08-18 确定）

> **定位澄清**：搜索工具**不是传统联网功能**——它是"特定内容源 + 特定工具"：让 BOT 依靠工具去 RSS/预设源搜特定内容（如某游戏的更新公告），返回结构化列表/详情。
> **现状问题**：工具不够强大。`query_news`/`fetch_source` 返回的只有标题/摘要列表（例：搜杀戮尖塔2 新闻返回几条标题），BOT **无法查看某一条的具体内容**（如一条更新公告的全文）→ 无法基于内容回答。

- 方向：搜索/抓取做成**两级能力**——① 列出结果（title/url/published_at/摘要）；② **取单条详情**（按条目 id 或 url 取全文/正文），让 BOT 真正读到内容。
- 待讨论：详情数据来源（`news_cache` 存全文 vs 只存摘要；`fetch_source` 抓取时正文是否入库；单条走缓存还是实时抓）；`fetch_source`/`query_news` 返回结构怎么改；是否加"按游戏/关键词预设"的搜索入口。

### H. 工作账单（2026-08-18 确定，实施中）

> 记账（bills）已闭环，新增**工作账单**域（装修安装门的工作记录）。与 bills **完全独立**、挂 **account**（家庭共享）、金额单位「分」。

- **5 张表**（005 迁移）：`work_clients`（委托方：A装修公司/B公司/个人）、`work_unit_prices`（单价表，**按委托方区分价格**）、`work_bills`（`contact`=服务对象文本 / `final_amount`=实际应收）、`work_bill_items`（明细：单价快照 + `price_ref_id`）、`work_settlements`（结算实收，一单多笔）。
- **委托方/服务对象分离**：委托方 = 跟谁结算（对账维度）；服务对象 = 门装到谁家（账单文本字段，不建表，查询走总账单 LIKE）。
- **金额**：`小计 = round(qty × 单价快照)`；`应收 = final_amount ?? Σ明细`；`已收 = Σ结算`；`欠款 = 应收 - 已收`；状态 = 未结算/部分/已结算（派生）。
- **recalc 纯手动**：改单价表**不自动级联**；`recalc_work_bills` 默认 dry_run 预览，范围可选「全部未结算 / 指定 bill_ids / 不更新」，apply 才提交；已结算单锁定，只动 `price_ref_id` 非空明细。
- **导出两模式**：summary 日常简版（明细平铺）/ statement 结账版（含计算式子 + 对账）。
- 15 个 `work_*` 工具 + `work_bill_stats`（40→56）；WEB 已加入待办 + 工作记账页面（方向 I，2026-08-18）。
- **keyword 搜索 + 统计已补**（2026-08-18）：`list_work_bills`/`export_work_bills` 支持 `keyword`（地址或备注）；`work_bill_stats` 区间统计（合计/按委托方/按月份 + chart 出图）。
- **每日推送已补**（2026-08-18）：`work_digest` 每晚 `bill_digest_time`（21:00）推送当日工作账单变动日报（新增/结算/修改/删除），开关 `work_digest_enabled`，outbox kind=`work_digest`，当日去重。
