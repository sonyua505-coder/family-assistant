## 1. 项目结构（实际实现）

**技术栈**：Node.js 22 + TypeScript + Fastify 5 + better-sqlite3（WAL）。ESM（`"type":"module"`），相对导入带 `.js` 后缀。

## 3. 工具注册（权威清单）

**与云端 `homeassistant-tools-inventory.md` 完全一致（50 个），本文档不再重复参数签名**，只强调注册时的硬约束与后端对应关系：

1. **工具名是既定契约**：已有 50 个名字（含语义）**不得改名/新建同义词**。新增工具前先对照 §2 端点表与 inventory：同作用必同名，新作用才新名字。
2. **身份不入参**：`x-platform`/`x-openid` 由插件从入站事件注入，LLM 猜不到也传不了。任何工具签名**不要**出现 platform/openid 参数。
3. **金额单位是「分」**：`amount` 工具层**直接收「分」整数**（`int(amount)`，1 元 = 100 分；插件**不做**元→分换算，需 LLM 自行换算，如 12.5 元 → 传 1250）。返回里的金额同样以「分」为单位。
4. **多账本歧义**：用户有多个账本时，记账/查账/待办需 `account_id`，否则后端 `ACCOUNT_AMBIGUOUS`，LLM 应反问指定。
5. **AA 规则**：`add_bill` 带 `participants`（名字数组）→ `status=pending`；`settle_bill` 结算。用户说「AA/平摊/垫付」先问清参与者。
6. **docstring 即工具描述**：AstrBot 用 docstring 生成 LLM 工具定义——参数名/类型/单位/枚举（如 type ∈ {income,expense}）都要写清。
7. **统一错误返回**：工具内 `self._api(...)` 失败返回失败字典（含 code/message），由 LLM 转述。

**已存在但未注册工具的端点**（云端可按需补，非必需）：`POST /news/:id/read`（标记已读，未读新闻在每日简报重复的关键）、`POST /subscriptions/:id/refresh`（手动刷新订阅）。

### 3.1 方向 A 新增端点契约（2026-08-16，云端已注册 `export_bills`/`bill_stats`）

新增两个端点，**均不改旧接口**（`GET /bills`、`GET /bills/stats` 等保持原样，供旧工具继续使用）：

- **`GET /api/v1/bills/export`** —— 全量宽过滤查询/导出（无分页上限）：
  - 参数：`type / category / status / participant / month / year / from / to / amount_min / amount_max / account_id / format`（`format=json|csv`，默认 json）。
  - `amount_min/amount_max` 单位「分」（非负整数，非法返回 `INVALID_AMOUNT_MIN/MAX`）。
  - json 返回 `{ total, applied, items }`：`applied` 回显**实际生效的筛选**（含金额/日期区间），`items` 金额「分」。
  - csv 返回 `text/csv; charset=utf-8`（UTF-8 BOM + 防公式注入，金额「元」人可读，全量）。
  - 按身份头隔离：只导出当前 person 可见账户（多账本需 `account_id`，否则 `ACCOUNT_AMBIGUOUS`）。
- **`GET /api/v1/bills/stats/range`** —— 区间统计（合计尊重区间，修正旧 `billStats` 合计不带 year/month 的问题）：
  - 参数：`from / to / year / month / category / amount_min / amount_max / account_id`。
  - 区间推导：显式 from/to 优先；year+month→当月；year→全年；都不给→全量。
  - 返回 `{ income, expense, net, by_category, trend, applied }`：`net = income - expense`；`applied` 回显生效的日期区间/分类/金额区间；金额「分」。

> 设计原则：查询/统计工具返回 `applied`（回显实际生效的筛选 + total），让 LLM 能发现自己解释错了筛选（静默的查询误判靠回显兜底）。统计转图像由云端插件 matplotlib 渲染（后端只出结构化数据），云端可自行决定工作区按人子目录方案。

### 3.2 方向 B 新增端点契约（2026-08-16，供云端文件导入工具）

- **`POST /api/v1/bills/import`** —— 宽容批量导入（文件解析后批量入库用，与 `/batch` 的全有或全无语义不同）：
  - body：`{ bills: [...], account_id? }`，`bills` 元素结构与 `CreateBillInput` 一致（`type/amount/category/note/occurred_at/participants`）；单次最多 **500** 笔（超限 `TOO_MANY`）。
  - **逐行校验、跳过坏行**：某行字段非法（`INVALID_TYPE`/`INVALID_AMOUNT`/`INVALID_CATEGORY`/`INVALID_OCCURRED_AT`）不阻断整批，合法行照常入库。
  - 返回 `{ ok, total, ok_count, fail_count, inserted: [{index, id}], failures: [{index, code, message}] }`：
    - `index` = 该行在 `bills` 数组中的下标（LLM 定位坏行）；
    - `failures` 每项含后端错误码 `code` + 中文 `message`；
    - 全失败也返回 200 + 明细（不是整批 400），让 LLM 看到每行错误。
  - 成功行记 `bill.create` 操作日志（供日报/变动查询）。
- **云端插件职责**（方向 B 链路）：`save_uploaded_file`（`await comp.get_file()` → 工作区 → 删 temp 副本）→ LLM 读取解析（CSV 解析在 LLM 侧，后端不解析）→ 调 `POST /bills/import` 入库；解析失败/导入 failures 反馈 LLM 自修正。

### 3.3 任务域读增强 + 记忆移除（2026-08-17）

**`GET /api/v1/tasks` 已增强**（读工具标准形态）：
- 参数：`q / category / is_done / from / to / page / page_size / account_id`。
- `q` = content 关键词，空格分隔多个词**须全部命中**（转义 LIKE，`content LIKE '%词%'` AND 逐词）；`from/to` 为创建日期 YYYY-MM-DD（非法返回 `INVALID_FROM/TO`）。
- `is_done` 缺省 = **未完成**（回显 `applied.is_done=false`）；返回 `{ items, total, page, page_size, applied }`。

**`GET /api/v1/tasks/export` 新增**（镜像 `/api/v1/bills/export`）：
- 参数：`is_done / q / category / from / to / account_id / format`（`format=json|csv`，默认 json）。
- `is_done` 缺省 = **全部**（区别于 `/tasks` 列表的默认未完成）。
- json 返回 `{ total, applied, items }`；csv 返回 `text/csv; charset=utf-8`（UTF-8 BOM + 防公式注入）。
- 按身份头隔离：只导出当前 person 可见账户（多账本需 `account_id`）。

**记忆功能已移除**：后端 `src/modules/memory/` 与 `GET/POST/DELETE /api/v1/memories` 端点删除，`user_memories`/`user_memories_fts` 表由 003 迁移 drop；插件 `remember`/`search_memory`/`forget` 工具移除。记忆改由 AstrBot 提示词/人设约定在工作区文件存储（云端侧配置，后端不管）。工具总数 42 → 40。

### 3.4 工作账单域契约（2026-08-18，云端待部署）

**画像已移除**：`GET /profile`、`PATCH /persons/me/profile` 端点与 `persons.profile_text` 列删除（004 迁移）；插件无引用，零改动。

**工作账单端点**（§2.4）：委托方 / 单价表 / 账单 / 结算 / recalc / export，挂 account（复用 `resolveAccountId`，多账本需 `account_id`，否则 `ACCOUNT_AMBIGUOUS` 409）。

硬约束：
1. **金额单位「分」**（1 元 = 100 分），`unit_price`/`amount`/`final_amount`/`settle amount` 全部整数分；qty 可为小数（㎡）。
2. **明细行即一切**：`金额 = Σ(qty × unit_price)`；明细单价**快照** + `price_ref_id` 指向单价表；手填价 `price_ref_id=null`。
3. **单价表按委托方区分**（`work_unit_prices.client_id`）；同名 upsert。删单价不影响历史账单快照。
4. **结算记实收**：`settle` 记任意金额（可多次/部分），`已收 = Σ`；`应收 = final_amount ?? Σ明细`；`欠款 = 应收-已收`；状态派生（unsettled/partial/settled）。
5. **recalc 纯手动**：改单价**不自动级联**；`POST /work-bills/recalc?dry_run=`（默认 true=预览）按 `bill_ids`（指定单）或 `client_id/from/to`（全部未结算）重算，`dry_run=0` 才提交；只动 `price_ref_id` 非空且未完全结算明细。
6. **export 两模式**：`mode=summary`（明细平铺）/ `mode=statement`（一单一列：式子 `品名 数量×单价元=金额元` + 计算总额/实际应收/已收/欠款/状态）；csv 带 BOM + 防公式注入。
7. **keyword 搜索**（2026-08-18）：`list_work_bills`/`export_work_bills` 支持 `keyword`（地址或备注包含，多 token AND 转义 LIKE），`applied` 回显 `keyword`。
8. **stats**（2026-08-18）：`GET /work-bills/stats?from&to&year&month&client_id&status&account_id` → `{ bill_count, receivable, paid, owed, by_client, by_month, applied }`（金额分）；区间推导复用 bills `resolveStatsRange`（from/to 优先 → year+month → year → 全量）。
9. **work_digest 每日推送**（2026-08-18）：每晚 `bill_digest_time`（默认 21:00）推送当日工作账单变动日报（新增/结算/修改/删除），接收人同 bill_digest（family=全成员/personal=本人），开关 `work_digest_enabled`（默认 true），outbox kind=`work_digest`，当日去重。

## 4. 调度任务（后端自动执行，插件无需实现）

| 任务 | 周期 | 行为 |

## 6. 记账 Web（能力令牌）

- 铸造 `create_ledger_link` → `POST /api/v1/web/tokens`，返回 `{url, token, expires_at}`；**token 明文仅回显一次**，库中只存 sha256。
- `url` = `PUBLIC_WEB_BASE` + `/w/` + token，浏览器经 ZeroTier 打开。
- mode=read 拒写；默认 30 分钟过期（`expires_in` 1-1440 分钟）；可 `revoke_ledger_link` 即时撤销。
- 安全：页面 EJS 全 `<%= %>` 转义 + CSP `script-src 'none'`；CSV 导出 `=+-@` 开头单元格加 `'` 前缀防公式注入；`/w` 访问日志 token 脱敏。

## 7. 功能变更 → 文档更新流程（维护约定）

本地每完成一次功能变更（新增端点/工具/适配器/调度/配置），必须同步：

1. **更新本文档**对应章节：新增端点进 §2 表、新工具名进 §3（先对照不重名）、新适配器进 §2.4、新调度进 §4、新配置进 §5。
2. **`npm run typecheck` + `npm run build`** 验证。
3. **推 GitHub**，云端 `git pull`。
4. **云端判断**是否需要补注册 LLM 工具（新端点若无对应工具，功能对用户不可达）——按 §3 硬约束补，补完更新云端 `homeassistant-tools-inventory.md`。

> 原则：**本地负责需求分析/设计/实现与文档；云端负责根据实际情况调整部署与工具注册。** 工具名以本手册 §3 + 云端 inventory 为唯一事实源，两端保持同步。
